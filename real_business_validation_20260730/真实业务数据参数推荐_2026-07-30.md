# 三份真实业务数据的资源参数推荐

日期：2026-07-30

## 结论

在 **H800 139.83 GiB、BF16、目标 GBS=64** 的前提下，当前暂时采用“最小安全卡数优先，同一卡数内再优化吞吐”的产品策略，首轮建议如下。

| 任务 | GPU | ZeRO | MBS/卡 | GA | cutoff | GC | packing | 结论 |
|---|---:|---:|---:|---:|---:|---|---|---|
| Qwen3-8B LoRA SFT | 1×H800 | 0 | 2 | 32 | 4096 | 关 | 关 | 单卡安全候选中 v4b 排名第 1 |
| Qwen3-14B Full SFT | 2×H800 | 3 | 2 | 16 | 4096 | 开 | 关 | 版本化显存锚点准入；两卡候选中 v4b 排名第 1 |
| Qwen2.5-VL-7B-Instruct LoRA SFT | 2×H800 | 3 | 1 | 32 | 4608 | 开 | 关 | 域外低置信度静态迁移推荐 |

其中：

```text
GBS = GPU 数 × 每卡 MBS × GA
```

资源推荐层暂时遵守以下决策链：

1. 用冻结 tokenizer 和模板生成纯静态数据画像，并生成不开 packing 的基线候选；
2. 对每个基线候选的 cutoff、MBS、GPU 数和 GBS 运行静态 packing 决策，
   输出 `off`、`on` 或 `hold_off`；
3. 当前统一显存与排序 Predictor 只消费 `packing=false` 分支；`on` 分支在
   packing-aware 显存和吞吐模型完成前只保留为 shadow；
4. 用 physical-shares 的中心值与 operational P95 做基础显存门控；
5. 基础 P95 过度保守时，只允许完全满足匹配条件的版本化历史锚点计算局部准入上界；
6. 先找满足显存和业务约束的最少卡数；
7. 只在这个最小卡数内部，用 v4b 选择安全候选中的最优配置；
8. 不因为更多 GPU 的总吞吐代理更高而自动扩卡；跨卡数吞吐排名和原
   70% 扩卡规则只保留为诊断信息。

8B 单卡配置由 physical-shares 直接放行，并在单卡候选内部由 v4b 选出。
14B 两卡配置的基础 P95 仍为 167.35 GiB/卡，但版本化锚点把最终准入
上界收敛到 130.87 GiB/卡，低于 132.84 GiB/卡安全线，因此两卡候选
可以进入排序并排在两卡第 1。这个变化只修正符合锚点匹配约束的局部
false reject，不改变 physical-shares 的全局参数。整个推荐过程没有启动
GPU 任务。当前 predictor 仍处于 `shadow_only`，绝对吞吐值不可作为 SLA。

## 2. 数据画像

两个纯文本数据集使用目标模型的真实 tokenizer 和 LLaMA-Factory `qwen3_nothink` 模板处理了全部记录。

| 数据集 | 均值 | P95 | P99 | 最大值 | 建议 cutoff 的截断样本率 | token 保留率 |
|---|---:|---:|---:|---:|---:|---:|
| `yt0jrk` + Qwen3-8B | 2,637.57 | 3,571.25 | 4,738.47 | 10,972 | 2.31% @ 4096 | 99.23% |
| `flieht` + Qwen3-14B | 1,041.32 | 2,868.25 | 6,281.59 | 28,799 | 2.16% @ 4096 | 93.71% |

VL 数据集的文本部分覆盖全部 7,108 条；视觉部分采用固定随机种子抽样 512 条，抽样中的 985 个唯一图片头全部解析成功。视觉 token 按 Qwen2.5-VL 的 resize、patch 和 merge 规则计算。

| VL 指标 | 结果 |
|---|---:|
| 每条图片数 | 2 |
| 估算总 token 均值 | 3,996.83 |
| P95 | 4,080 |
| P99 | 4,112.78 |
| 抽样最大值 | 4,121 |
| `cutoff=4096` 截断率 | 3.71%，但只损失约 0.0135% 的总 token |
| `cutoff=4608` 截断率 | 0/512 |

因此 VL 首轮取 4608，而不是直接放大到 8192。它覆盖当前抽样尾部，并降低不必要的激活显存。

## 3. 推荐配置

### 3.1 Qwen3-8B LoRA SFT

```yaml
model: /wanqing-models/Qwen3-8B
template: qwen3_nothink
num_gpus: 1
deepspeed_zero_stage: 0
per_device_train_batch_size: 2
gradient_accumulation_steps: 32
global_batch_size: 64
cutoff_len: 4096
gradient_checkpointing: false
packing: false
bf16: true
lora_rank: 32
lora_alpha: 32
lora_dropout: 0.0
lora_target: all
attention_kernel: fa3_orig
enable_liger_kernel: true
optimizer: adamw_torch_fused
```

理由：

- 单卡存在通过 physical-shares 门控的候选，因此最小安全卡数为 1；
- 在安全的单卡候选中，v4b 将 `MBS=2、GC 关闭` 排在第 1；
- 单卡的 physical-shares operational P95 为 80.71 GiB，相对 132.84 GiB 的 95% 安全线还有 52.13 GiB；
- 历史相同资源配置已有一次成功实测，reserved 为 72.38 GiB；
- `cutoff=2048` 会截断 96.69% 的样本，不可接受；4096 是数据保真和资源之间更合理的点。

诊断输出仍会保留 2 卡和 4 卡的吞吐代理，以及历史扩卡结果，但它们不改变当前单卡推荐。以后若恢复“训练时间优先”的策略，应先通过发布前离线实验校准扩卡模型，不能在单次用户推荐前临时跑卡。

### 3.2 Qwen3-14B Full SFT

```yaml
model: /wanqing-models/Qwen3-14B
template: qwen3_nothink
num_gpus: 2
deepspeed_zero_stage: 3
per_device_train_batch_size: 2
gradient_accumulation_steps: 16
global_batch_size: 64
cutoff_len: 4096
gradient_checkpointing: true
packing: false
bf16: true
attention_kernel: fa3_orig
enable_liger_kernel: true
optimizer: adamw_torch_fused
```

Qwen3-14B Full 在不使用 CPU/NVMe offload 的当前搜索空间内，单卡无法容纳完整 Adam 训练状态；两卡 ZeRO-3 是最小可行起点。当前产品策略不再自动检查或触发 2→4 扩卡，因此默认停在两卡。

当前模型与历史实测存在明显分歧：

| 证据 | 结果 |
|---|---:|
| physical-shares center | 129.58 GiB/卡 |
| 基础 operational P95 | 167.35 GiB/卡，因此基础模型拒绝 |
| 锚点合格成功证据 | 2 次 runtime-complete，来自 2 个不同 job |
| 锚点辅助证据 | 1 次 legacy 成功 |
| 同配置 OOM 证据 | 0 次 |
| 历史 maximum observed reserved | 127.39 GiB/卡 |
| 历史实测保护值：`127.39 × 1.02` | 129.94 GiB/卡 |
| 模型中心保护值：`129.58 × 1.01` | 130.87 GiB/卡 |
| 最终局部准入上界 | `max(129.94, 130.87) = 130.87 GiB/卡` |
| 相对 132.84 GiB 安全线的余量 | 1.97 GiB/卡 |
| 历史实测有效吞吐中位数 | 4,242.50 token/s |

这里的锚点绑定 Qwen3-14B Full、2×H800、ZeRO-3、GC 开、MBS=2、
cutoff=4096、GBS=64、BF16、kernel 路径和 runtime mechanism 的版本。
当前业务 case 与锚点配置完全一致。新业务数据在 cutoff 后的平均长度为
975.85，而历史参考数据约为 1,176.03；这只能作为“输入没有更重”的辅助
信息，不能代替显存安全保护值。

这说明 coarse Full + ZeRO-3 + GC 残差桶在这个 case 上过度保守。局部锚点
的准入公式是：

```text
anchor_upper = max(
  maximum_observed_reserved × 1.02,
  physical_center × 1.01
)
```

当前两卡推荐使用冻结的历史证据和新数据静态画像，而不是推荐前短跑。
最终安全余量只有 1.97 GiB/卡，而且锚点证据参与了本次局部回放，尚不是
冻结后新增的独立验收集。因此它只能标记为中等置信度的 `shadow` 结果，
不能据此宣称全局显存模型的泛化精度已经提升。缺少合格锚点的相似输入
仍按基础 P95 拒绝或返回“不在自动支持域”。

`cutoff=4096` 的代价是只保留 93.71% 的原始 token。如果业务更看重长样本，可在两卡基线通过后追加以下高保真候选：

```yaml
num_gpus: 2
deepspeed_zero_stage: 3
per_device_train_batch_size: 1
gradient_accumulation_steps: 32
cutoff_len: 8192
gradient_checkpointing: true
```

该候选保留 98.03% 的 token，但没有完全匹配的两卡 ZeRO-3 实测，因此当前不选它。

### 3.3 Qwen2.5-VL-7B-Instruct LoRA SFT

```yaml
model: /wanqing-models/Qwen2.5-VL-7B-Instruct
template: qwen2_vl
num_gpus: 2
deepspeed_zero_stage: 3
per_device_train_batch_size: 1
gradient_accumulation_steps: 32
global_batch_size: 64
cutoff_len: 4608
gradient_checkpointing: true
packing: false
bf16: true
image_max_pixels: 589824
image_min_pixels: 1024
lora_rank: 16
lora_alpha: 32
lora_dropout: 0.05
lora_target: all-linear
freeze_language_model: false
freeze_vision_tower: true
freeze_multi_modal_projector: true
attention_kernel: flash_attn
optimizer: adamw_torch_fused
```

这是一个**低置信度静态迁移推荐**，不是 predictor 已证明安全的配置。现有 physical-shares 没有视觉塔、projector 和图像 token 激活项；历史 Qwen3-VL 回放已经证明直接套纯文本模型会严重低估显存。

采用 `2×H800 + ZeRO-3 + GC + MBS=1` 的依据是：附近的 Qwen3-VL-8B LoRA 实验在同样 2×H800、ZeRO-3、GC、MBS=1、cutoff=4096 下成功；同时已有业务 VL baseline 也把 2/4 卡、MBS=1、GBS=64、LoRA rank=16、冻结视觉塔和对齐层作为可运行起点。

这两条迁移证据仍不足以形成 VL 显存安全证明，因此正式产品在 VL 模型完成发布前应返回“支持域外、低置信度启发式配置”，而不能伪装成已验证推荐。推荐前不会为了这个用户数据启动 GPU 短跑。若业务目标要求训练视觉塔或 projector，需要重新静态判断，不能直接沿用上述配置。

## 4. 纯静态 packing v1 的判断

packing 决策器只读取 tokenizer 之后的长度画像、cutoff、不开 packing 时的
MBS、GBS 和冻结策略，不读取任何推荐时 GPU 实测。它按 LLaMAFactory
当前装箱方式模拟物理序列数、装箱利用率、GBS 误差和理论线性 token
效率，再输出 `on`、`off` 或 `hold_off`。

| 任务 | 关键静态指标 | v1 决策 | 当前输出 |
|---|---|---|---|
| Qwen3-8B LoRA | 装箱利用率 65.77%；序列减少 2.82%；每包 1.03 个样本；理论线性效率 72.01% | `off`：收益门槛未通过 | `packing=false` |
| Qwen3-14B Full | 装箱利用率 96.78%；序列减少 75.38%；每包 4.06 个样本；理论线性效率 1.279×；GBS 误差 1.53% | `hold_off`：收益门槛全部通过，但 Full 尚未进入已发布 ON 域 | `packing=false`，保留为离线实验候选 |
| Qwen2.5-VL-7B LoRA | 多模态样本边界、图片展开与 collator 语义未被当前策略覆盖 | `off`：结构性不支持 | `packing=false` |

所以三项当前都输出 `packing=false`，但原因并不相同：8B 是静态收益不足，
14B Full 是“看起来有收益但证据域不足”，VL 是结构性不支持。14B 的
`hold_off` 正是下一轮发布前 paired packing 实验的优先 case；用户推荐时
不会临时跑 A/B。

## 5. 置信度与边界

| 配置 | 当前置信度 | 原因 |
|---|---|---|
| Qwen3-8B LoRA | 中等偏高 | 单卡显存余量充分，且是单卡候选内部排名第 1 |
| Qwen3-14B Full | 中等 | 版本化锚点修复了定点 false reject，但最终安全余量仅 1.97 GiB/卡，且缺少冻结后独立验收 |
| Qwen2.5-VL-7B LoRA | 低 | 现有显存与排序模型都不覆盖真实视觉输入 |

学习率、epoch、warmup 和 weight decay 不由资源 predictor 推导。若没有业务侧既有 recipe，可把 `LoRA: 1e-4`、`Full: 1e-5`、`warmup_ratio: 0.03`、cosine scheduler 作为试跑起点，但应通过 loss/质量指标单独选择，不应解释为本资源模型的输出。
