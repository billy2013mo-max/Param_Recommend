# SFT 训练效率推荐流程

## Overview

当前训练任务的参数配置不合理，或者环境依赖不足，导致性能极低，

在训练效果约束不变的前提下，先通过静态数据分析确定 `cutoff\_len` 和是否开启 packing，再联合搜索资源与执行参数，选择最小可行资源下预计训练吞吐最大，时间最短的方案。

进阶：可否不仅限最小资源，以提高效率

## 2. 用户输入与固定参数

联合搜索前由用户确认并固定：

- 模型、训练类型、数据集
- epoch、学习率，LoRA rank、alpha 等训练参数，scheduler 固定cosine
- GBS 

## 3. 数据集静态分析

[Qwen 系列 Tokenizer 在不同类型数据集上的统计总结](https://docs.corp.kuaishou.com/d/home/fcADN95dyVWMdfjQTzQ-iwCC9)

使用实际训练模板和 tokenizer 处理数据集，统计：

- 样本 token 长度的 P50、P90、P95、P99、max
- 决定先用Qwen3模型做token分析，且需要监控预估token和实际token的差异

## 4. 静态确定 cutoff\_len

取数据集样本长度分析结果max值，并向上取整到512的倍数

## 5. 静态决定是否开启 packing

Neat Packing 说明：

### 1. 启用 Neat Packing时等效MBS说明

受限于当前 Neat Packing 与 FlashAttention的实现机制，物理MBS固定为 1。但由于每个 packed batch 可容纳多个逻辑样本，因此可采用**平均样本数**作为样本粒度下的等效 MBS，后续利用这个平均样本数去反解出GA

### 2. 对训练效果的影响

由于各 packed batch 所含逻辑样本数量存在差异，仅基于平均样本数估算 GA，虽能在长期统计意义上使实际 GBS 趋近目标值，但单步梯度更新的样本量仍存在波动。

更严谨的做法是：在每个 optimizer step 中动态控制累计参与梯度计算的实际样本总数，使其严格逼近目标 GBS。该方式可最大程度保障训练动力学与“非 packing、固定 MBS”场景下的一致性。

综上：平均样本数适用于工程层面的快速估算；若需严格对齐训练语义，则应以每个 optimizer step 的实际样本数为控制基准。

在已确定的 `cutoff\_len` 下，使用与线上训练一致的packing算法，分别模拟packing = false，packing = true，

对代表性 MBS（如 1、2、4、8）和多个特定 shuffle seed，统计：

- 实际处理 token 数
- packing 前后的有效token率
- 每个 pack 包含的原始样本数分布，例如pack内平均样本个数，即实际batch size
- 不同 shuffle seed 下收益的波动 （理想情况下波动很小）

默认决策规则：

```plain text
保守节省比例 >= 15%，且 pack 利用率 >= 90%：开启 packing
最大节省比例 <= 5%：关闭 packing
收益处于 5%～15%：默认关闭 packing
```

经过该阶段后输出唯一 DataPlan，后续不再搜索 `cutoff\_len` 和 packing：

```plain text
cutoff_len
packing
截断与 token 保留指标
每个 epoch 的有效 token 数和计算 token 数
pack 数量及每个 pack 的样本数分布

```

## 6. 联合搜索空间

DataPlan 固定后，联合搜索空间为：

```plain text
GPU 卡型与数量 × ZeRO 策略 × gradient checkpointing × MBS
约束：如果不 packing, MBS <= GBS / GPU数  
```

其中：

- Zero stage 候选为 None、1、2、3，按当前训练类型和框架能力过滤。
- GA 根据用户固定的 GBS 派生，不作为独立搜索变量。
- packing 场景应使用 pack-aware 调度，保持约定的样本级或 token 级 GBS。

## 7. 遍历与剪枝顺序

先将 GPU 配置按照平台定义的资源等级从小到大排列。同一等级内包含资源规模相近的不同卡型和卡数组合。

```plain text
    for GPU 卡型和卡数组合：
        使用静态下界模型排除必然显存不足的配置

        for ZeRO 策略：
            for GC in {关闭, 开启}：
                估算当前组合的最大可用 MBS

                for MBS 候选：
                    根据固定 GBS 派生 GA 或 pack-aware 调度
                    	- 如果 packing，只需考虑MBS=1和 seq_len=cutoff_len的显存情况
                    检查 GBS、整除关系及分布式调度约束
                    预测显存峰值并排除 OOM 方案: 建模+实验
                    检查稳定性约束
                    预测训练吞吐/时间
                    保存可行方案

    如果当前资源等级存在可行方案：
        在该等级内选择预计训练时间最短的方案
        停止搜索更高资源等级

```

MBS 不需要遍历所有整数，可从以下集合中生成候选：

```plain text
1、2、4、8、预测最大可用 MBS，以及满足 GBS 调度要求的边界值

```

GA 的基本关系为：

```plain text
非 packing：GBS = DP × MBS × GA
packing：根据固定 GBS 口径和每个 pack 的样本/token 分布派生调度

```

## 8. 推荐结果

最终输出一个默认方案：

```plain text
cutoff_len
packing
GPU 卡型和数量
MBS
GA 或 pack-aware 累积方式
GBS 及其口径
gradient checkpointing
ZeRO 策略
预计显存峰值
预计训练时间
数据截断与保留指标
packing 预计收益

```

总体流程为：

```plain text
用户固定训练效果参数和数据约束
-> 数据集 tokenize 与统计分析
-> 静态确定 cutoff_len
-> 静态决定 packing
-> 生成唯一 DataPlan
-> 按资源等级搜索 GPU、ZeRO、GC 和 MBS
-> 派生 GA 并进行显存、稳定性和时间评估
-> 选择最小可行资源下预计训练时间最短的方案

```
