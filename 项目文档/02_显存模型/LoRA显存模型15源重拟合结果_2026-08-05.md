# LoRA 显存模型 15 源重拟合结果

日期：`2026-08-05`

状态：`第一阶段 77 个作业已完成；M1 仅作为 shadow 候选；触发第二阶段 20 源 / 60 作业；生产模型未修改`

后续更新：历史数据迁移已经完成，325 条严格绑定的旧观测已按新长度口径加入重拟合。更新后的结果见 [历史显存数据迁移与 M1 重拟合结果](历史显存数据迁移与M1重拟合结果_2026-08-05.md)。本文件以下数值保留为“加入历史数据之前”的可追溯基线。

## 1. 最终结论

这批实验支持“non-packing 的物理显存应使用 profile max，而不是一律使用 cutoff_len”这一判断，而且证据很强：

- 只用 `cutoff_len` 的物理 allocated anchor，19 源 source-equal MAPE 为 `29.95%`；
- 改为 `effective_sequence = round_up(min(cutoff_len, profile_max), 8)` 后，MAPE 降为 `6.19%`；
- LoRA 上的改善最大，从 `41.24%` 降到 `6.79%`；
- Full 从 `7.34%` 降到 `6.59%`，说明 Full 原本对长度错误不那么敏感。

因此，profile max 应直接进入物理层。不能再使用 cutoff_len 拟合出来的旧系数去补偿这个错误。

但 `max/cutoff` 不应再作为一个常数或额外线性项重复加入回归层。M2、M3 都没有改善 M1，相关系数在 leave-source-out 各折中还跨过 0，说明其符号不稳定。最终选择的是：

```text
M1 = effective sequence 物理 anchor + 不含 ratio 项的残差校准
```

M1 现在还不能发布。critical LoRA 范围内虽然没有 false-safe OOM，reserved upper 覆盖也是 `100%`，但 admission recall 只有 `78.05%`，reserved center source-equal MAPE 为 `20.68%`。此外 95% expansion 阈值仍由单个最大场景决定。因此必须先做第二阶段 20 个新独立源、60 个作业，再重拟合；不能直接进入正式 prospective holdout。

## 3. 为什么原来的 LoRA 特别不准

原模型的核心问题不是 profile max 本身不对，而是训练数据和物理 anchor 曾经都按 cutoff_len 表达。在样本明显短于 cutoff 时，模型把没有实际参与当前 batch padding 的 token 也算进了激活显存。

LoRA 对这个错误特别敏感，原因是：

1. LoRA 的参数、梯度和优化器固定显存比 Full 小，激活显存在总量中的相对占比更高；
2. sequence length 写大以后，激活显存误差会更直接地变成总显存相对误差；
3. Full 的参数、梯度和优化器显存占比更大，相同的 sequence 偏差会被固定项稀释。

实测结果与这个物理解释一致：

| 模式 | cutoff anchor MAPE | effective-sequence anchor MAPE |
|---|---:|---:|
| LoRA | 41.24% | 6.79% |
| Full | 7.34% | 6.59% |
| 全部 | 29.95% | 6.19% |

这也回答了“是不是原来用 cutoff_len 拟合，换 profile max 后旧系数不准”：是。旧系数部分吸收了错误的长度定义，不能原样迁移到新的物理 anchor。

## 4. 为什么不能只用 profile max 得到最终 reserved

profile max 能很好解释实际 allocated，但最终做显存准入时需要预测的是跨所有 rank 的 reserved 上界。reserved 还受到 CUDA allocator 分段、碎片、MBS、卡数和 DDP rank 不对称等影响。

例如旧 education 场景中，同一 2-GPU 作业的 rank0 reserved 为 `97.512 GiB`，rank1 为 `117.803 GiB`。准入若只看 rank0 会明显低估风险。

critical LoRA 2-GPU 场景观测到的最大 `reserved/allocated` expansion 为 `2.3462`，来自 `dataset-64de8r-1785128542`，其 effective fraction 为 `0.625`。不同源的 expansion 并不随 `max/cutoff` 单调变化。因此正确分层应为：

```text
profile max -> 物理 allocated anchor
训练机制/MBS/卡数等 -> 小幅中心残差校准
独立 source 尾部分数 -> reserved 安全上界
```

其中 allocated 残差层带来的改善已经不大：effective anchor 单独为 `6.19%`，M1 nested source-equal MAPE 为 `4.98%`。这说明物理 anchor 是主要修复，回归层只做小幅修正；后续仍应保留“纯物理 anchor + reserved tail”的简化候选作对照，防止 19 个源上使用过多残差特征。

## 5. M0～M3 消融结果

### 5.1 19 源 nested leave-source-out

| 方案 | allocated MAPE | reserved MAPE | upper 覆盖 | recall | false-safe OOM | unsafe success admitted |
|---|---:|---:|---:|---:|---:|---:|
| M1：effective，无 ratio | **4.98%** | **15.42%** | 98.95% | 71.23% | 0 | 0 |
| M2：M1 + 全局 log ratio | 5.12% | 16.20% | 98.95% | 71.23% | 0 | 0 |
| M3：M2 + critical LoRA 交互 | 5.51% | 16.13% | 98.95% | 71.23% | 0 | 0 |

M2 和 M3 的 allocated、reserved 中心误差都没有优于 M1。所有 ratio 系数的 outer-fold 范围都跨过 0；M3 的全局 allocated ratio 项符号一致率只有 `78.95%`。因此不能把 `max/cutoff` 当成稳定的额外修正项。

### 5.2 与冻结 M0 的同配置对比

冻结 M0 只支持 69 个新唯一配置中的 46 个；MBS=4、4-GPU 等 23 个配置不在其支持域。下表只比较双方都支持的同一批 46 个配置：

| 方案 | allocated MAPE | reserved MAPE | upper 覆盖 | recall |
|---|---:|---:|---:|---:|
| M0：冻结 cutoff 模型 | 18.82% | 19.80% | 73.33% | 92.31% |
| M1：effective，无 ratio | **3.18%** | **12.46%** | **100%** | 76.92% |
| M2 | 3.41% | 12.99% | 100% | 76.92% |
| M3 | 3.72% | 13.22% | 100% | 76.92% |

M1 明显修复了 M0 的中心误差和漏覆盖，但当前安全尾部过于保守，因而 recall 下降。这不是 profile max 方向错误，而是 19 源下 95% conformal 只能取最大场景分数造成的。

## 6. 候选范围内的真实状态

候选只面向：

```text
H800 + LoRA + ZeRO-2 + GC-off + 2 GPU + non-packing
```

超出该范围继续使用当前冻结模型，不由这个 shadow candidate 覆盖。

| 指标 | 19 源 critical LoRA | 新 15 源 critical LoRA |
|---|---:|---:|
| 唯一配置 | 53 | 45 |
| allocated source-equal MAPE | 5.29% | 3.21% |
| reserved source-equal MAPE | 20.68% | 16.79% |
| reserved upper 覆盖 | 100% | 100% |
| admission recall | 78.05% | 81.82% |
| false-safe OOM | 0 | 0 |
| unsafe success admitted | 0 | 0 |

全配置 98.95% 覆盖中的唯一漏覆盖来自 4-GPU LoRA，位于当前候选范围之外；critical 2-GPU 范围本身是 100% 覆盖。

## 7. 为什么必须进入第二阶段

第一阶段计划预先定义了四个触发条件。本次至少命中以下四项：

| 触发项 | 当前结果 | 是否触发 |
|---|---:|---:|
| critical admission recall < 90% | 78.05% | 是 |
| critical reserved center MAPE > 20% | 20.68% | 是 |
| 95% expansion 上界由经验最大值决定 | 2.3462，rank 19/19 | 是 |
| ratio 系数跨折符号或量级不稳定 | M2、M3 均不稳定 | 是 |

19 个独立源做完整拟合时，95% finite-sample 阈值合法，但必须取第 19 个、也就是经验最大值。nested outer fold 每次只剩 18 个训练源，形式上的最大可保证覆盖率只有 `18/19 = 94.74%`，所以当前 nested coverage 只是校准诊断，不是发布验收。

第二阶段按原计划新增：

| 实验组 | 新独立源 | 每源作业 | 作业数 | 目标总独立源 |
|---|---:|---:|---:|---:|
| Critical LoRA expansion 扩充 | 20 | 3 | 60 | 39 |

达到 39 源后，95% 阈值取第 38 个场景分数，即第二大值，不再被单个最大场景完全控制。第二阶段完成后必须重新运行同一套 M0～M3 source-disjoint nested 拟合，再冻结新候选，之后才能生成全新 prospective holdout。

## 8. 当前不能宣称的内容

- 不能说新模型已经发布或可以替换生产模型；
- 不能把这 19 个校准源当成 prospective holdout；
- 不能因为校准覆盖 100% 就宣称泛化验收通过；
- 不能把 `max/cutoff` 系数固化进生产模型；
- 不能把 4-GPU、Full、packing 或其他 ZeRO/GC 机制纳入当前候选支持域。
