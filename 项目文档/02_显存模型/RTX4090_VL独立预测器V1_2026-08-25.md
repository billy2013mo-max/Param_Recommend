# RTX 4090 VL 独立预测器 V1

**日期**：2026-08-25
**产物**：`offline_experiments/artifacts/rtx4090_vl_v1_predictor.json`
**代码**：`offline_experiments/scripts/{fit,predictor}_rtx4090_vl_v1.py`

---

## 1. 要干的事

给 4090 上的 VL LoRA 训练做参数推荐前，需要一个独立、干净的显存/吞吐预测器：

- **显存**：给定配置能不能装进 24 GiB，装的话峰值多少
- **吞吐**：给定配置的 tok/s 预估，用于比较不同参数组合

原有 4090 预测器绑定 SHA 三层不一致，`git revert` 修不好，从头重拟合更合算
（见记忆 `rtx4090-predictor-binding-broken`）。这次显式选择独立发布，不与
H800/A100 数据混合——混合会让 24 GiB 上限被大机型的数据拉高，反而不安全。

## 2. 数据来源与规模

144 组 4090 上实测的 VL 观测：

- `matrix_results_fixed.jsonl`（108 组）：多卡矩阵，`{model, dataset, mbs, gc, zero, gpu_count}` 张成
- `single_card_sweep.jsonl`（36 组）：单卡文本 smoke 数据，不用于 VL 拟合（`track=text_smoke` 标注）

用于拟合的**有效 VL 样本 108 条**，其中 44 条成功（用于中心拟合）、64 条 OOM
（用于准入召回验证）。

## 3. 模型形式

### 3.1 显存模型（线性 ridge，特征在原始 MiB 空间）

$$\text{peak\_center\_mib} = \text{intercept} + \sum_i w_i \cdot f_i$$

$$\text{peak\_upper\_mib} = \text{peak\_center\_mib} + \text{safety\_margin}$$

**9 个特征**（`f_i`）：

| 特征 | 含义 |
|---|---|
| `const` | 框架常驻开销 |
| `weight_gib` | BF16 权重占用，ZeRO-3 下按 `param_gib / gpu_count` |
| `mbs` | 基础激活 + KV cache（对 mbs 线性） |
| `activation` | `mbs × tokens_per_sample / 1000` |
| `activation_gc_off` | 关 GC 时额外的激活（`activation × (1-gc)`） |
| `is_4b_activation` | Qwen3-VL-4B 的激活比 3B 贵（更大 hidden） |
| `z2_optim_shard` | ZeRO-2 优化器分片（`is_z2 / gpu_count`） |
| `z3_optim_shard` | ZeRO-3 优化器 + 权重双分片 |
| `z3_bias` | ZeRO-3 all-gather 峰值加成（常数） |
| `z3_mbs` | ZeRO-3 下 mbs 对 all-gather 缓冲的额外压力 |

**安全边际**：拟合完后计算 `residual = actual - predicted` 在成功行上的分布，
取正残差的 95 分位数作为 `safety_margin`（当前为 2453 MiB）。
上界 = 中心 + 边际。

**准入决策**：`admitted = peak_upper_mib + 800 < 24564`（额外 800 MiB 头
留给运行时波动）。

### 3.2 吞吐模型（log 空间 ridge）

$$\log(\text{tokens\_per\_s}) = \text{intercept} + \sum_i v_i \cdot g_i$$

**8 个特征**（`g_i`）：

| 特征 | 含义 |
|---|---|
| `const` | log 基准吞吐 |
| `log_mbs` | MBS 扩展 |
| `log_gpu` | 卡数扩展 |
| `neg_gc` | GC 损失 |
| `neg_log1p_tokens_kt` | 序列越长每 sample 越慢 |
| `neg_log_param_scale` | 参数量惩罚 |
| `z3_pcie_penalty` | ZeRO-3 在 PCIe 上的额外惩罚项 |
| `z2_scaling` | ZeRO-2 正常线性扩展 |

## 4. 拟合质量

### 4.1 显存模型（LOO 交叉验证）

| 指标 | 值 |
|---|---:|
| 训练样本数（成功 VL 行） | 44 |
| LOO RMSE | 1312 MiB |
| LOO MAE | 1088 MiB |
| 安全边际（残差 P95） | 2453 MiB |
| **OOM 召回**（TP/total） | **64/64 = 100%** |
| ok 行误拒 | 3/44 = 6.8% |

3 个误拒都在 3B/z2/mbs=2 或 4 的边界配置上，实测 peak 21000 MiB 左右，
预测上界 24000-25000 MiB。方向偏保守，不会把 OOM 配置放进来，只会拒绝
一些能跑的配置——从推荐系统角度是安全端错误。

### 4.2 吞吐模型

| 指标 | 值 |
|---|---:|
| 训练样本 | 44 |
| LOO log-RMSE | 0.228 |
| 近似 MAPE | 18.6% |

用于**相对排序**足够（同一实验矩阵内的相对优劣不会被 20% 误差颠倒），
用于**绝对预测**偏大。绝对误差最大的几条集中在 z2/z3 单卡组合上，样本
稀疏是主因。

## 5. 举例说明预测行为

四个典型配置的预测与实测对照：

| 配置 | 预测 center | 预测 upper | admit | 预测 tok/s | 实测 peak | 实测 tok/s |
|---|---:|---:|:---:|---:|---:|---:|
| 3B / blind_f1 / 单卡 / mbs1 / gc | 9695 | 12147 | ✓ | 1288 | 8861 | 1265 |
| 3B / blind_f2 / 2 卡 z2 / mbs2 | 21819 | 24272 | ✗ | 4812 | 21265 | 5937 |
| 4B / blind_f2 / 4 卡 z2 / mbs1 | 20131 | 22584 | ✓ | 7839 | 21659 | 7896 |
| 4B / calib_f2 / 2 卡 z2 / mbs2 | 61041 | 63494 | ✗ | — | OOM (24209) | — |

- 第 1 行：中心偏高 800 MiB（+9%），tok/s 差 2%。是理想情况
- 第 2 行：中心偏差 3%，但 upper 24272 + 800 headroom 超过卡容量，
  admit=False——这是刚才提到的「保守误拒」的一个具体例子
- 第 3 行：中心低估 1500 MiB（-7%），upper 覆盖到 22584，安全通过
- 第 4 行：外推到极端配置，中心预测 61 GiB 显然是外推区，但方向对（拒绝）

## 6. 已知边界

1. **cutoff_len 恒定 4096**：VL 拟合数据全在 4096 上跑（VL 单卡矩阵实测
   过 c8192，显存变化 < 5%，不作为变量入模）；给定其它 cutoff 时预测器不
   保证正确
2. **模型集限死两个**：`qwen25vl3b` 和 `qwen3vl4b`；`model_meta` 里可以
   加，但需要新数据才能拟合它们的系数
3. **数据集范围有限**：`{blind_f1, blind_f2, blind_f4, calib_f2}` 有对
   应的 `tokens_per_sample` 查表；其它数据集必须显式给
   `tokens_per_sample=int`
4. **外推极端配置会失控**：例如上表第 4 行预测 61 GiB，数值本身无意义，
   只有 `admit=False` 的方向可信。推荐系统里应加一层「> 40 GiB 视为
   显性无解」的规则，避免用户看到 61 GiB 疑惑
5. **只覆盖 LoRA**：所有拟合数据都是 LoRA + 冻结 vision tower + 冻结
   MM projector。full-parameter 训练未测过，别用这个预测器

## 7. 复用方式

```python
from predictor_rtx4090_vl_v1 import RTX4090VLPredictor
p = RTX4090VLPredictor.load()
r = p.predict({
    "model": "qwen25vl3b",
    "dataset": "blind_f2",  # 或 tokens_per_sample=1739
    "mbs": 2,
    "gpu_count": 2,
    "zero": "z2",
    "gc": False,
})
# r["admitted"] 决定是否推荐，r["tokens_per_s"] 给出预估吞吐
```

`predictor_rtx4090_vl_v1.py` 底部有 `_demo()` 可直接跑，看四个基线例子的
预测输出。
