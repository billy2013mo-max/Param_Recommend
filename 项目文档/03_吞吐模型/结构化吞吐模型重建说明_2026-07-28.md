# 结构化吞吐模型重建说明（2026-07-28）

## 1. 结论先行

本轮已经按照“物理工作量主干 + 共享效率校正 + 小型卡型适配器 + 绝对值/排序联合训练”的思路，重新完成了吞吐建模和阻塞式留出验证。

当前模型不再把 `model_id`、`dataset_id` 或卡型名称作为共享模型的输入，也不是给旧吞吐公式简单乘一个常数。它先根据模型结构、数据长度分布、训练配置和硬件参数计算理论耗时，再学习理论公式没有覆盖干净的效率损失。

冻结模型使用：

- 391 个成功候选配置；
- 148 个训练场景；
- 1268 个同场景配置对；
- 2 种卡型：H800、RTX 4090；
- 5 个 Qwen3 模型量级：0.6B、1.7B、4B、8B、14B；
- 6 种数据分布。

和上一版“平坦的全因素联合模型”相比，最重要的改进是：

- H800 场景等权 MAPE：18.24% 降到 14.98%；
- 4090 场景留出 MAPE：14.46% 降到 13.36%；
- 4090 完整模型留出 MAPE：51.02% 降到 28.86%；
- 4090 完整模型留出的排序准确率：77.94% 提高到 94.12%。

但是，这不等于已经能对任意模型、任意数据集和任意卡型给出同等可信的预测。当前最可靠的用途仍然是：

1. 先由显存模型过滤 OOM 风险；
2. 对训练支持域内的安全候选配置预测吞吐并排序；
3. 对新模型、新数据集或新卡型明确降低置信度；
4. 必要时用少量校准实验更新卡型适配器。

## 3. 模型输入

模型只使用运行前可以得到的信息。

### 3.1 模型结构

- 基础参数量、加载参数量、可训练参数量；
- 层数、隐藏维度、中间层维度、KV 宽度；
- LoRA adapter 参数量；
- 每次前向传播的线性层参数应用量。

### 3.2 用户配置

- Full 或 LoRA；
- GPU 数、MBS、目标 GBS；
- cutoff length；
- gradient accumulation；
- gradient checkpointing；
- ZeRO-0、ZeRO-2、ZeRO-3；
- packing；
- FA2、FA3、Liger、fused CE、fused optimizer、compile 等执行机制。

### 3.3 数据集静态画像

- token 长度均值、标准差、P90、P99；
- label token 比例；
- 平均轮数；
- 在指定 cutoff、MBS 和 packing 设置下的预计有效 token、计算 token 和 attention token pair。

这里没有把运行后采集到的 `effective_tokens`、`computed_tokens` 或 step time 当作预测输入。静态重建与运行观测的中位数比例为：

| 卡型 | 有效 token | 计算 token | attention token pair |
|---|---:|---:|---:|
| H800 | 0.994 | 1.005 | 1.007 |
| RTX 4090 | 1.023 | 1.014 | 1.013 |

### 3.4 硬件参数

- BF16 dense 峰值算力；
- HBM 带宽；
- 卡间通信带宽；
- collective latency；
- 显存容量。

共享模型使用的是这些连续硬件量，而不是 `H800` 或 `4090` 名称 one-hot。

## 4. 数学模型

### 4.1 静态工作量

记：

- \(W_{\mathrm{eff}}\) 为每 step 的预计有效 token；
- \(W_{\mathrm{comp}}\) 为每 step 的预计计算 token；
- \(A\) 为每 step 的预计 attention token pair；
- \(G\) 为 GPU 数。

Full fine-tuning 的主要线性层 FLOPs 为：

$$
F_{\mathrm{linear,full}}
=
6P_{\mathrm{linear}}W_{\mathrm{comp}}
$$

LoRA 的主要线性层 FLOPs 为：

$$
F_{\mathrm{linear,lora}}
=
4P_{\mathrm{linear}}W_{\mathrm{comp}}
+
6P_{\mathrm{adapter}}W_{\mathrm{comp}}
$$

Attention FLOPs 为：

$$
F_{\mathrm{attention}}
=
6LHA
$$

开启 gradient checkpointing 时，再加入前向重计算所需的线性层和 attention FLOPs。

### 4.2 五个正耗时分量

模型计算五个物理下界：

$$
\tau_{\mathrm{compute}}
=
\frac{F_{\mathrm{total}}}
{G C_{\mathrm{peak}}}
$$

$$
\tau_{\mathrm{hbm}}
=
\frac{B_{\mathrm{kernel}}}
{B_{\mathrm{hbm}}}
$$

$$
\tau_{\mathrm{optimizer}}
=
\frac{B_{\mathrm{optimizer}}}
{B_{\mathrm{hbm}}}
$$

$$
\tau_{\mathrm{comm}}
=
\frac{B_{\mathrm{collective}}}
{B_{\mathrm{link}}}
+
N_{\mathrm{collective}}t_{\mathrm{latency}}
$$

$$
\tau_{\mathrm{launch}}
=
N_{\mathrm{launch}}t_{\mathrm{launch}}
$$

为了保证耗时始终为正，对每个分量学习逆效率倍数：

$$
m_{k,c}
=
1+\operatorname{softplus}(a_k+u_{c,k})
$$

其中 \(a_k\) 是两种卡共享的参数，\(u_{c,k}\) 是强正则约束下的卡型偏移。未知卡型令 \(u_{c,k}=0\)。

Compute 与 kernel HBM 通过平滑 roofline 合并：

$$
\tau_{\mathrm{roof}}
=
\left[
(m_{\mathrm{compute}}\tau_{\mathrm{compute}})^4
+
(m_{\mathrm{hbm}}\tau_{\mathrm{hbm}})^4
\right]^{1/4}
$$

物理主干的 step time 为：

$$
\tau_{\mathrm{physical}}
=
m_{\mathrm{launch}}\tau_{\mathrm{launch}}
+
\tau_{\mathrm{roof}}
+
m_{\mathrm{optimizer}}\tau_{\mathrm{optimizer}}
+
m_{\mathrm{comm}}\tau_{\mathrm{comm}}
$$

### 4.3 共享校正与卡型适配器

模型有 35 个共享结构特征 \(z\)。它们包括训练机制、资源几何、计算/带宽比、通信占比、数据长度分布以及少量有物理含义的交互项。

卡型适配器只作用在 8 个预先选定的特征上：

- Full/LoRA；
- gradient checkpointing；
- ZeRO-3；
- GPU 数；
- MBS；
- compute/HBM 比；
- communication/roofline 比；
- launch/roofline 比。

原始校正为：

$$
r_c
=
b+\beta^\mathsf{T}z+\gamma_c^\mathsf{T}z_S
$$

为了避免小数据下校正项无限外推，将其限制在对数空间的固定范围内：

$$
\delta_c
=
1.25\tanh\left(\frac{r_c}{1.25}\right)
$$

最终 step time 和吞吐预测为：

$$
\widehat{\tau}
=
\tau_{\mathrm{physical}}\exp(\delta_c)
$$

$$
\widehat{T}
=
\frac{W_{\mathrm{eff}}}{\widehat{\tau}}
$$

因此，排序分数就是同一个 \(\widehat{T}\)，没有再训练一个与绝对吞吐互相矛盾的独立排序头。

未知卡型同时令 \(u_{c,k}=0\) 和 \(\gamma_c=0\)，只使用共享主干，并将结果标记为低置信度。

## 5. 联合训练目标

训练目标同时约束绝对预测和排序：

$$
\mathcal{L}
=
\lambda_{\mathrm{abs}}\mathcal{L}_{\mathrm{Huber,abs}}
+
\lambda_{\mathrm{mag}}\mathcal{L}_{\mathrm{Huber,pair}}
+
\lambda_{\mathrm{order}}\mathcal{L}_{\mathrm{logistic,pair}}
+
\lambda_{\mathrm{list}}\mathcal{L}_{\mathrm{KL,list}}
+
\mathcal{R}
$$

四部分分别表示：

1. 绝对对数吞吐误差；
2. 两个配置之间吞吐差值的误差；
3. 配置先后顺序是否正确；
4. 同一场景内整个候选列表的相对分布是否正确。

固定权重为：

| 项 | 权重 |
|---|---:|
| 绝对吞吐 Huber | 1.00 |
| pairwise 差值 Huber | 0.50 |
| pairwise 排序 logistic | 0.02 |
| listwise KL | 0.05 |
| 共享校正 L2 | 0.02 |
| 卡型适配器 L2 | 0.10 |
| 全局物理效率先验 | 0.02 |

这些权重在阻塞式留出验证前固定，没有针对某个留出集合逐项搜索。

## 6. 参数规模与泛化约束

两种卡型一起训练时共有 67 个标量参数：

- 5 个共享物理效率参数；
- 10 个卡型物理分量偏移，即每卡 5 个；
- 35 个共享校正系数；
- 16 个卡型残差系数，即每卡 8 个；
- 1 个截距。

这和“391 行数据直接拟合 67 个任意 one-hot 特征”不同：

- 大部分模型尺度、数据长度和硬件影响已由确定性公式吸收；
- 没有模型 ID、数据集 ID 的记忆项；
- 卡型参数有更强的 L2 约束；
- 校正幅度被 `tanh` 限制；
- 训练时按卡型和场景等权，避免候选多的场景支配损失；
- 用完整场景、完整模型、完整数据集和完整卡型留出检验外推。

冻结模型的全局逆效率倍数约为：

| 分量 | 倍数 |
|---|---:|
| launch | 5.43 |
| compute | 2.85 |
| kernel HBM | 2.00 |
| optimizer HBM | 2.01 |
| communication | 2.08 |

H800 与 4090 的分量倍数非常接近，说明当前结果主要由共享物理主干解释，而不是靠两套完全独立的卡型模型记忆。

## 7. 更改前后指标

以下 MAPE 均为场景等权值；pairwise accuracy 为同场景候选配置的两两排序准确率；regret 越低越好。

| 验证协议 | 旧模型 MAPE | 新模型 MAPE | 旧 pairwise | 新 pairwise | 旧场景 Top-1 regret | 新场景 Top-1 regret |
|---|---:|---:|---:|---:|---:|---:|
| H800 固定留出 | 18.24% | 14.98% | 89.09% | 90.39% | 0.27% | 1.75% |
| 4090 完整场景留出 | 14.46% | 13.36% | 92.65% | 94.12% | 0.81% | 0.58% |
| 4090 完整模型留出 | 51.02% | 28.86% | 77.94% | 94.12% | 4.12% | 0.58% |

H800 的场景 Top-1 regret 有回退，但固定 GPU 数后的 regret 从 2.55% 改善到 1.46%。这说明“平均排序更准”和“每个场景一定选到更好的第一名”不是同一个指标，不能声称所有指标都同步改善。

新模型新增的完整留出结果：

| 验证协议 | 场景等权 MAPE | pooled pairwise | 场景等权 pairwise | 场景 Top-1 regret |
|---|---:|---:|---:|---:|
| 完整数据集留出 | 19.49% | 93.45% | 85.40% | 1.24% |
| 只用 H800 训练，预测未知 4090 | 21.55% | 94.12% | 94.12% | 0.58% |
| 只用 4090 训练，预测未知 H800 | 28.20% | 75.97% | 83.62% | 3.81% |

完整卡型迁移是明显不对称的，因此目前不能把“两张卡上的联合拟合不错”解释为“任意新卡都能直接准确预测”。

## 8. 误差范围怎么使用

冻结 JSON 中保存了以下经验 P90 绝对百分比误差：

| 情况 | P90 APE |
|---|---:|
| 已知 H800、当前原生留出 | 34.22% |
| 已知 4090、场景留出 | 29.39% |
| 未见模型 | 61.94% |
| 未见数据集 | 48.60% |
| H800 训练后迁移到 4090 | 50.32% |
| 4090 训练后迁移到 H800 | 74.52% |

这些是历史留出上的经验误差参考，不是严格的统计置信区间。对于排序任务，未见模型的 94.12% pairwise accuracy 比 28.86% MAPE 更有意义；对于容量规划或精确训练时长估计，则不能忽略绝对误差。

## 9. 当前支持域

冻结模型中已经保存每个特征的 min、P05、median、P95 和 max。主要训练支持范围为：

- 基础模型参数量：0.752B 至 14.768B；
- GPU 数：1、2、4；
- MBS：1、2、4、8、16、32；
- cutoff length：512、2048、4096、8192、16384、32768；
- GBS：16、64、256；
- 训练模式：Full、LoRA；
- ZeRO：0、2、3；
- packing：只有 `false`。

此外，当前主要证据都来自 dense Qwen3；Liger、fused CE 和 fused optimizer 在训练数据中始终开启，compile 始终关闭。这些未发生变化的机制无法从当前数据中独立识别其因果效果。

因此以下情况必须判为低置信度：

- packing 为 `true`；
- 新架构或 MoE 模型；
- 超过 14.8B 很多的模型；
- 8 卡或跨节点；
- 新卡型；
- 关闭当前固定 kernel 组件或开启 compile；
- 特征明显超出冻结 JSON 中的训练范围。

## 10. 代码验证与复现

优化器为带解析梯度的 L-BFGS-B，184 次迭代后正常收敛。

对 20 个参数进行了中心差分核验：

- 最大绝对梯度误差：\(2.09\times10^{-11}\)；
- 最大缩放梯度误差：\(2.24\times10^{-8}\)。

复现命令：

```bash
python offline_experiments/scripts/structured_throughput_modeling.py
```

该脚本只做 CPU 建模，不会启动 GPU 实验，也不会修改实验队列。它会重建并覆盖：

```text
offline_experiments/artifacts/static_workload_profiles.json
offline_experiments/artifacts/structured_throughput_modeling.json
```

## 11. 当前状态

本轮已经完成“离线模型重建 + 冻结参数 + 阻塞式验证”，并增加了统一的 Python API 与命令行预测器。具体用法见 [`统一吞吐预测器使用说明_2026-07-28.md`](统一吞吐预测器使用说明_2026-07-28.md)。

当前尚未接入线上推荐服务，也没有在 Predictor 内部执行显存安全过滤。要形成最终推荐器，还需要把调用链固定为：

```text
用户需求和静态数据画像
    -> 枚举候选资源/参数配置
    -> 显存安全模型过滤
    -> 本吞吐模型预测并排序
    -> OOD/置信度检查
    -> 返回推荐配置和备选配置
```

在当前证据下，可以对支持域内候选配置进行有用的吞吐排序；还不能承诺对任意模型、任意数据集和任意卡型都给出同等准确的绝对吞吐。
