# 统一吞吐预测器使用说明（2026-07-28）

> 注意：本文描述的是较早的结构化单头吞吐预测器，它不执行显存安全检查。H800 当前的 physical-shares + v4b 统一封装请以 `../01_项目总览与使用指南/H800统一资源配置预测器使用说明_2026-07-30.md` 为准。

## 1. 当前封装

吞吐模型现在已经封装为统一的 `ThroughputPredictor`，同时支持：

- Python API 单配置预测；
- Python API 多候选预测和组内排序；
- 命令行读取 JSON 或 JSONL；
- 已知 H800、RTX 4090 的简化硬件输入；
- 自定义模型结构和自定义硬件物理参数；
- 训练支持域、卡型支持域和 OOD 检查；
- 经验 P90 误差参考；
- step time 和计划训练时间估计；
- 可选物理分量与 35 个结构化特征解释。

主要文件：

| 内容 | 路径 |
|---|---|
| Predictor 实现 | `offline_experiments/scripts/throughput_predictor.py` |
| 示例请求 | `offline_experiments/examples/throughput_predictor_request.json` |
| 自动化测试 | `offline_experiments/tests/test_throughput_predictor.py` |
| 冻结吞吐模型 | `offline_experiments/artifacts/structured_throughput_modeling.json` |
| 数据集静态画像 | `offline_experiments/artifacts/dataset_profiles/` |

## 2. 命令行使用

执行示例请求：

```bash
python offline_experiments/scripts/throughput_predictor.py \
  --input offline_experiments/examples/throughput_predictor_request.json \
  --output /tmp/throughput_prediction.json
```

输出完整物理解释：

```bash
python offline_experiments/scripts/throughput_predictor.py \
  --input offline_experiments/examples/throughput_predictor_request.json \
  --output /tmp/throughput_prediction_explained.json \
  --explain
```

查看可用模型、数据集、硬件和冻结支持范围：

```bash
python offline_experiments/scripts/throughput_predictor.py \
  --show-catalog
```

标准输入也可以使用：

```bash
python offline_experiments/scripts/throughput_predictor.py \
  --input -
```

## 3. 最小输入

单个候选配置：

```json
{
  "request_id": "candidate-a",
  "model_id": "qwen3_4b",
  "dataset_id": "multiturn_2048",
  "hardware_id": "h800",
  "training_mode": "lora",
  "gpu_count": 2,
  "physical_mbs": 2,
  "target_gbs": 64,
  "cutoff_len": 2048,
  "gradient_checkpointing": false,
  "zero_stage": 2,
  "packing": false
}
```

多候选配置可以直接传 JSON 数组，也可以使用：

```json
{
  "candidates": [
    {"request_id": "candidate-a"},
    {"request_id": "candidate-b"}
  ]
}
```

数组中的每个对象都必须包含完整配置。

### 3.1 必填字段

| 字段 | 含义 |
|---|---|
| `model_id` | 模型清单中的 ID，或自定义模型的标识 |
| `dataset_id` | 静态 profile 中的数据集 ID |
| `hardware_id` | `h800` 或 `rtx4090`；自定义硬件时可省略 |
| `training_mode` | `full` 或 `lora` |
| `gpu_count` | GPU 数量 |
| `physical_mbs` | 每卡 micro batch size |
| `target_gbs` | 目标 global batch size |
| `cutoff_len` | 截断长度 |

### 3.2 可选字段

| 字段 | 默认值 | 含义 |
|---|---:|---|
| `gradient_checkpointing` | `false` | 是否重算 |
| `zero_stage` | `0` | 0、1、2、3 或 `zero2` 等字符串 |
| `packing` | `false` | 是否 packing；当前会标记低置信度 |
| `dtype` | `bf16` | 当前只有 BF16 训练证据 |
| `kernel_path` | 按卡型选择 | H800 默认 FA3，4090 默认 FA2 |
| `lora_rank` | 32 | 非 32 会降置信度 |
| `planned_steps` | 无 | 输出预计总训练秒数 |
| `total_effective_tokens` | 无 | 输出固定 token 预算的预计秒数 |
| `comparison_group` | 自动生成 | 强制指定候选排序组 |

当 `packing=false` 时，必须满足：

```text
target_gbs % (gpu_count * physical_mbs) == 0
```

为了兼容现有实验矩阵，Predictor 也接受以下别名：

```text
train_type -> training_mode
mbs        -> physical_mbs
gc         -> gradient_checkpointing
zero       -> zero_stage
gpu_type   -> hardware_id（字符串中包含 H800 或 4090）
```

## 4. Python API

在项目目录运行时：

```python
import sys

sys.path.insert(0, "offline_experiments/scripts")

from throughput_predictor import ThroughputPredictor

predictor = ThroughputPredictor()

prediction = predictor.predict(
    {
        "request_id": "candidate-a",
        "model_id": "qwen3_4b",
        "dataset_id": "multiturn_2048",
        "hardware_id": "h800",
        "training_mode": "lora",
        "gpu_count": 2,
        "physical_mbs": 2,
        "target_gbs": 64,
        "cutoff_len": 2048,
        "gradient_checkpointing": False,
        "zero_stage": 2,
        "packing": False,
    },
    explain=True,
)

print(prediction["predicted_effective_tokens_per_second"])
print(prediction["predicted_step_seconds"])
print(prediction["confidence"])
```

多候选排序：

```python
report = predictor.predict_many(
    [candidate_a, candidate_b, candidate_c],
    explain=False,
)

for group in report["ranking_groups"]:
    print(group["ranked_request_ids"])
```

## 5. 排序规则

Predictor 使用以下字段自动定义一个可比较场景：

- 模型；
- 模型结构与 LoRA rank；
- 数据集；
- Full/LoRA；
- GBS；
- cutoff；
- packing；
- dtype。

GPU 数、MBS、ZeRO 和重算可以不同，因为它们正是需要排序的候选参数。

不同训练场景不会被强行放在同一排行榜中。需要人工合并时，可以给候选设置相同的 `comparison_group`，但调用方需要自行保证它们确实可比较。

排序使用的分数就是同一个预测：

```text
predicted_effective_tokens_per_second
```

没有额外的独立排序头。

## 6. 主要输出

每个候选返回：

| 字段 | 含义 |
|---|---|
| `predicted_effective_tokens_per_second` | 主要吞吐预测与排序分数 |
| `predicted_step_seconds` | 预计 step time |
| `predicted_computed_tokens_per_second` | 根据同一 step time 推导的计算 token/s |
| `predicted_logical_samples_per_second` | 预计逻辑样本/s |
| `rank_within_group` | 当前比较组内名次 |
| `work_per_step` | 静态重建的有效/计算 token 等工作量 |
| `confidence` | 支持域、原因和经验误差参考 |
| `time_estimates` | 可选的计划训练时间 |
| `memory_safety_checked` | 当前固定为 `false` |
| `report_sha256` | 输出内容的完整性校验哈希 |

使用 `--explain` 时还会返回：

- 模型结构参数；
- 硬件物理参数；
- FLOPs 分解；
- HBM、optimizer、通信和 launch 分量；
- 35 个结构化特征。

## 7. 置信度

### `supported`

配置位于全局支持域和当前卡型支持域内，模型、数据集及主要机制都有对应证据。

### `caution`

数值仍有一定验证依据，但发生了结构迁移，例如：

- 新模型 ID，但参数规模仍在全局范围内；
- 某个模型只在另一种卡上训练过；
- LoRA rank 不同；
- 某个离散资源值在全局见过、当前卡没有见过。

### `low`

属于没有可靠误差保证的外推，例如：

- 未知卡型；
- packing；
- 模型量级超出 0.75B 至 14.77B；
- 非 dense Qwen3 或 MoE；
- 非 BF16；
- 结构化特征超出全局 min/max；
- 冻结模型与输入文件哈希不一致。

`low` 仍会返回一个数值，便于做探索性比较，但不能把该数值当作已校准预测。

## 8. 自定义模型

不在清单中的模型可以传入 `model`：

```json
{
  "model_id": "custom_dense_model",
  "model": {
    "id": "custom_dense_model",
    "family": "qwen3",
    "actual_parameters": 6000000000,
    "hidden_size": 3584,
    "intermediate_size": 10240,
    "num_hidden_layers": 32,
    "num_attention_heads": 28,
    "num_key_value_heads": 4,
    "vocab_size": 151936,
    "max_position_embeddings": 32768
  }
}
```

还需要在同一个对象中提供数据集、硬件和训练配置。模型几何能够计算不代表一定在支持域内；Predictor 会根据架构和参数范围降级置信度。

## 9. 自定义硬件

未知卡型可以传入：

```json
{
  "hardware": {
    "hardware_id": "custom_gpu",
    "card_id": "custom_gpu",
    "memory_bytes": 80000000000,
    "dense_bf16_peak_flops_per_gpu": 500000000000000,
    "hbm_bandwidth_bytes_per_second": 2000000000000,
    "intra_node_bandwidth_bytes_per_second": 200000000000,
    "collective_latency_seconds": 0.00001,
    "default_kernel_path": "fa3_orig+liger_fused_ce+adamw_torch_fused"
  }
}
```

未知卡型没有卡型适配器，自动使用：

```text
共享物理效率参数 + 零卡型偏移 + 零卡型残差
```

结果会标为 `low`。

## 10. 新数据集

新数据集必须先准备运行前 token profile：

```text
<dataset_id>.qwen3_nothink.jsonl
```

每行至少需要：

```json
{
  "total_tokens": 1536,
  "label_tokens": 768,
  "turns": 4
}
```

将该文件放在一个单独目录，然后使用：

```bash
python offline_experiments/scripts/throughput_predictor.py \
  --input request.json \
  --additional-dataset-profile-dir /path/to/new_profiles
```

新增画像会和训练时的固定画像合并，但不允许覆盖已有数据集 ID。新数据集预测会标为 `caution`，并使用完整数据集留出的经验误差作为参考。

`--dataset-profile-dir` 用于替换训练画像根目录，一般不应修改；`--allow-binding-mismatch` 只用于审计或调试，不建议在常规预测中使用。

## 11. 显存安全边界

Predictor 只预测吞吐，不判断 OOM。输出中会明确包含：

```json
{
  "requires_memory_safety_filter": true,
  "memory_safety_checked": false
}
```

最终推荐流程必须是：

```text
候选配置
  -> 显存安全过滤
  -> ThroughputPredictor
  -> 按 effective tokens/s 排序
```

不能把吞吐排名第一但会 OOM 的配置直接推荐给用户。
