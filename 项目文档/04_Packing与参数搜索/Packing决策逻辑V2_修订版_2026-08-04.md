# Packing 决策逻辑 V2（2026-08-04 修订版）

## 背景

neat packing 强制 `per\_device\_batch\_size = 1`,因此在 packing 下 `cutoff\_len`** 直接决定每步每卡的 token 数(= cutoff\_len),是吞吐量的核心旋钮**。若把 cutoff 只设成"数据集分析得到的最长样本长度",在大显存 GPU 上会严重欠载,发挥不出性能。

## 1. cutoff\_len 尽量加长,但上界不是 max\_position\_embeddings

在候选区间内取若干值作为 cutoff 候选:

```plain text
[data_max_len  ..  上界]
```

- **下界 **

   `data\_max\_len`:数据集最长样本长度(向上取整到 512 的倍数),保证不截断真实样本。
- **上界不能盲取 **`max\_position\_embeddings`。吞吐对 cutoff **不是单调递增**,且越长激活显存越大。上界应取三者的最小值:
   ```plain text
   上界 = min( max_position_embeddings,
               显存可行上限,        # 由显存规划器给出:预测峰值 ≤ 0.95×容量
               GBS 可控上限 )        # 见第 2 节

   ```
> 「不知道 GPU 型号所以定不了上界」——这正是显存规划器要解决的:给定 GPU 型号,直接用它选出\*\*预测可行的最大 cutoff\*\*,无需盲扫到 max\_position\_embeddings。
> 
> ⚠️ 注意规划器已知盲区:LoRA + 标准 dense 模型预测可信且偏保守;\*\*全参微调大模型 / VL 视觉模型的显存会被低估\*\*,对这两类选 cutoff 上界时需额外留余量。

## 2. global batch size 如何保证

packing 下 GBS 天然按\*\*样本数\*\*会波动(每个 pack 装的样本数是变的),这是 packing 的固有性质。真正需要稳定的是 **token/step**;样本级 GBS 用梯度累积逼近。这里必须把“epoch 平均值”和“单步分布上尾”分开，不能都用一个 `n_pack_upper` 表示：

```plain text
n_pack_mean_center ≈ cutoff × pack_utilization_center / 平均样本长度
n_pack_mean_upper  = epoch平均samples/pack的置信上界
n_pack_step_p99    = 单个pack内逻辑样本数分布的P99上界
grad_accum         = max(1, round(GBS / (n_pack_mean_center × GPU数)))
期望epoch样本级GBS ≈ n_pack_mean_center × GPU数 × grad_accum

```

`n_pack_mean_center` 的长度分母仍使用平均样本长度，不能使用中位数。数据上传期完成一次 tokenizer/template 后，异步静态 packer 应按 `dataset/profile/tokenizer/template/packer/sharding fingerprint` 缓存候选 cutoff 对应的紧凑分布，例如 `{mean,p50,p90,p95,p99,max}`；推荐请求只读取这些缓存统计，不重新 tokenize、读取原始长度数组或执行完整 pack。缓存未命中时可以由 DataProfile 预测，但必须给出经标定的 mean 上界和 step-P99 上界。

**GBS 可控上限(关键约束,即原方案第 3 点)**:当一个全局 microstep 的样本数上尾在 `grad_accum=1` 时已经超过目标 GBS，由于 `grad_accum ≥ 1`,\*\*物理上无法再降到目标 GBS\*\*。因此必须满足:

```plain text
n_pack_step_p99 × GPU数 ≤ GBS × (1 + 允许误差)

```

违反此式的 cutoff 直接淘汰。`pack_utilization` 的不确定性只能形成 `n_pack_mean_upper`，不能替代 pack 内样本条数分布的 P99；后者受短样本集中、长尾、shuffle 和 rank sharding 影响。首版用 `单rank P99×DP` 作为保守全局 microstep 上界，后续有足够分布标定后可换成直接预测“多 rank 求和”的 P99。

短吞吐 probe 的少量窗口也不能当作 epoch 平均 GBS。报告必须区分 `expected_epoch_GBS` 和 `observed_probe_window_GBS`。2026-08-04 的 W4 复核中，完整静态 packer 得到 mean=`30.612`、2 卡 GA=1 的 `expected_epoch_GBS=61.224`，说明均值公式正确；短 probe 的 `50.25` 只是固定窗口观测。真正触发过滤的是单 pack P99=`60`，保守全局上尾为 `60×2=120`，超过目标 `64×1.1=70.4`。

## 3. 防止 step 数量过小

设每个 pack 平均样本量为 `n_pack_mean_center`,总 pack 数 `packs`,则真实\*\*优化器步数\*\*为:

```plain text
opt_steps = packs × epochs / (GPU数 × grad_accum)

```

安全下界使用 epoch 平均样本数的置信上界，而不是 step-P99：

```plain text
packs_lower     = 样本总数 / n_pack_mean_upper
opt_steps_lower = packs_lower × epochs / (GPU数 × grad_accum)
```

要求 `opt_steps_lower ≥ K`。注意与原方案的两点修正:

- 步数由 pack 数、GPU 数、grad\_accum 共同决定,\*\*不能只靠控制 n\_pack\*\*。
- 方向修正:cutoff 越长 → `n\_pack` 越大 → packs 越少 → **步数越少**。所以"加长 cutoff"(第 1 节要吞吐)与"步数够多"(本节)是\*\*同一个 cutoff 的取舍\*\*,不是两条独立规则。

> `K` 的设定建议以\*\*总优化器步数\*\*为准(涵盖 warmup/decay 所需的最小步数,并考虑 epoch 杠杆),而非只看单个 epoch。具体取值需进一步调研。

## 4. 联合决策(把第 1、2、3 节合并成一次选择)

第 1 节(加长 cutoff 提吞吐)与第 3 节(限制 cutoff 保步数)方向相反,应在\*\*同一循环里联合裁决\*\*,而不是分设两条互相打架的规则:

```plain text
给定 (model, GPU型号, dataset, 目标GBS):
  1. cutoff 候选 = 粗网格 + GA/显存/GBS/步数事件点 + 边界附近512精搜
  2. 对每个候选 cutoff:
       读取缓存/预测 n_pack_mean_center、n_pack_mean_upper、n_pack_step_p99
       grad_accum    = max(1, round(GBS / (n_pack_mean_center × GPU数)))
       expected_epoch_GBS = n_pack_mean_center × GPU数 × grad_accum
       opt_steps_lower = (样本总数 / n_pack_mean_upper) × epochs / (GPU数 × grad_accum)
       # 三个硬门槛,任一不过则淘汰:
       显存可行:  预测峰值 ≤ margin × 容量   (full-FT/VL 用更小 margin)
       GBS 可控:  n_pack_step_p99 × GPU数 ≤ GBS × (1+误差)
       步数达标:  opt_steps_lower ≥ K
  3. 在存活候选中,选**预测吞吐最高**的 cutoff

```

这样上下界都已在门槛里施加,选吞吐最高者即在"填满 GPU"与"步数够多 / GBS 可控"之间取得平衡。

## 待调研 / 待实测

- `K` 的具体取值(对收敛效果的影响)。
- `epsilon_GBS` 的默认值，以及单 rank P99×DP 相对直接全局 microstep P99 的保守程度。
- 样本级 GBS 波动对 SFT 效果是否有实质影响(packing 训练本就如此,预期无害,需实测确认)。
- 长 cutoff 下 `pack\_utilization` 是否仍近似恒定(当前假设:cutoff ≫ 平均样本长度时基本持平)。
- 确认 neat packing 使用\*\*块对角注意力 mask\*\*(跨文档互不 attend)——这是正确性前提,也是"attention 代价随 cutoff 近似线性、非平方"的依据。
