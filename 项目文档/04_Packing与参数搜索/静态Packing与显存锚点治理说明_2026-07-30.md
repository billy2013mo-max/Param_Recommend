# 静态 Packing 与显存锚点治理说明

日期：2026-07-30

## 1. 本轮结论

本轮完成了三个可运行、可审计的能力：

1. 建立纯静态 packing v1。推荐时只读取冻结的数据画像和训练配置，
   不启动 GPU 任务，也不做在线 A/B。
2. 为 Qwen3-14B Full 两卡被过度保守过滤的问题建立版本化显存锚点。
   基础 physical-shares P95 仍完整保留，只对满足锚点约束的局部 case
   使用受保护的准入上界。
3. 建立锚点库和显存模型的版本治理规则。锚点库不可原地改写；如果要
   真正替换 physical-shares 模型，必须使用冻结后未见过的验收集，并同时
   满足安全、覆盖率、中心误差和分片不退化要求。

当前推荐链为：

```text
静态数据画像
  -> 生成不开 packing 的基线候选
  -> 对每个基线形状做静态 packing 决策
  -> physical-shares 基础显存门控
  -> 必要时查询版本化历史锚点
  -> 选择最小安全卡数
  -> 仅在该卡数内用 v4b 排序
```

以上链路在用户推荐阶段全部是 CPU 静态计算。历史 GPU 实验只在离线构建
冻结产物时使用。当前统一显存与吞吐 Predictor 仍只支持
`packing=false`；静态 `on` 会生成 packing shadow 分支，只有
packing-aware 显存和吞吐验收完成后才能并入最终资源排序。这是当前仍需
补齐的集成边界。

## 2. 纯静态 packing v1

### 2.1 输入与输出

输入由以下字段组成：

- tokenizer 和模板处理后的逐样本 `total_tokens`；
- `model_id`、`train_type`、模态、dtype 和 GPU family；
- `cutoff_len`；
- 不开 packing 时的 `MBS`；
- GPU 数、data parallel 数和目标 GBS；
- packing 算法版本与预处理 worker 数。

输出包含：

- `packing=true/false`；
- `decision=on/off/hold_off`；
- 是否允许自动采用；
- 全部静态特征、门槛及未通过原因；
- 数据画像、策略文件和请求文件的 SHA-256；
- 明确的 `pre_recommendation_gpu_execution=false`。

三种决策的含义是：

| 决策 | 含义 | 返回给训练配置 |
|---|---|---|
| `on` | 静态收益门槛全部通过，并且位于已发布 ON 域 | `packing=true` |
| `off` | 结构不支持或至少一个收益门槛不通过 | `packing=false` |
| `hold_off` | 静态指标有利，但该训练类型或模型域尚未完成离线验收 | `packing=false`，保留影子候选 |

### 2.2 静态模拟原理

设样本数为 `N`，cutoff 为 `C`。packing 使用的有效容量为 `C - 1`。
长度先变为：

```text
packing_length[i] = min(total_tokens[i], C - 1)
```

然后按照当前 LLaMAFactory 的实现，将数据切成 8 个连续 worker 分片，
每个分片独立运行 largest-fitting-item greedy knapsack。假设最终得到
`P` 个 pack，各 pack 的 token 数为 `used_tokens[j]`，则：

```text
pack_utilization
  = sum(used_tokens[j]) / (P * (C - 1))

sequence_reduction_ratio
  = 1 - P / N

mean_samples_per_pack
  = N / P
```

不开 packing 时，按指定 MBS 和 5 个固定 shuffle seed 模拟动态 padding：

```text
padding_utilization
  = effective_tokens
    / sum(batch_size * maximum_sequence_length_in_batch)
```

当前使用的理论线性效率比为：

```text
linear_token_efficiency_ratio
  = model_facing_pack_fill_ratio
    / mean_no_packing_padding_utilization
```

它是低成本的方向性指标，不是对真实 tokens/s 的承诺。策略还根据
`N / P` 推导 packing 后每个物理序列包含的平均逻辑样本数，并选择最接近
目标 GBS 的整数 GA，避免 packing 改变有效 batch 语义太多。

### 2.3 v1 门槛

只有以下门槛全部通过，才形成静态 `on` 候选：

| 门槛 | v1 阈值 |
|---|---:|
| 画像记录数 | 至少 1,000 |
| 装箱利用率 | 至少 90% |
| 物理序列减少率 | 至少 15% |
| 平均每个 pack 的样本数 | 至少 1.5 |
| packing 后预期 GBS 相对误差 | 不超过 5% |
| `cutoff / no-packing MBS` | 至少 1,024 |
| 理论线性效率，原 MBS=1 | 至少 0.9 |
| 理论线性效率，原 MBS>1 | 至少 1.1 |

最后一个占用门槛 `cutoff / MBS` 很重要。历史实验显示，在短序列场景中，
不开 packing 可以使用很大的 MBS；即使 packing 能把多个样本装进一个
序列，也可能因 packed physical MBS 固定为 1 而损失 GPU 占用率。

### 2.4 当前证据和边界

v1 在已有 10 个完整 H800 Qwen3 LoRA paired point 上回放为：

| 指标 | 结果 |
|---|---:|
| 总点数 | 10 |
| ON / OFF | 6 / 4 |
| 判断正确 | 10 / 10 |
| false positive / false negative | 0 / 0 |

这 10 个点同时参与了阈值校准，所以这是 calibration resubstitution，
不是独立泛化结果。每个 treatment 也只有一次历史运行，并非 ABBA 重复。
因此当前允许自动开启的域只包含 H800、纯文本、BF16、SFT、Qwen3-8B/14B
LoRA；Full SFT 的正向结果仍返回 `hold_off`，VL 直接返回结构性 `off`。

### 2.5 三份业务数据的静态结果

| 业务 case | 关键结果 | 决策 |
|---|---|---|
| Qwen3-8B LoRA，cutoff 4096，MBS 2 | 利用率 65.77%，序列减少 2.82%，理论效率 0.720× | `off` |
| Qwen3-14B Full，cutoff 4096，MBS 2 | 利用率 96.78%，序列减少 75.38%，理论效率 1.279×，GBS 误差 1.53% | `hold_off`，因为 Full 尚未验收 |
| Qwen2.5-VL-7B LoRA | 多模态边界和 collator 语义不在策略内 | 结构性 `off` |

## 3. 14B 两卡为何被过度保守过滤

目标配置是：

```text
Qwen3-14B Full
2 x H800
ZeRO-3
GC=true
MBS=2
cutoff=4096
GBS=64
packing=false
```

基础模型的结果是：

| 量 | 结果 |
|---|---:|
| physical-shares center | 129.58 GiB/卡 |
| 历史 maximum observed reserved | 127.39 GiB/卡 |
| H800 95% 安全线 | 132.84 GiB/卡 |
| 基础 operational P95 | 167.35 GiB/卡 |

中心值只比实测高约 2.19 GiB，主要物理公式并没有在该 case 上明显失准。
真正造成拒绝的是成功残差尾部。当前 selector 是：

```text
[Full, ZeRO-3, GC=true, packing=false]
```

这个桶合并了 58 个不同模型规模、MBS 和 cutoff 的成功样本，其 log residual
P95 为 0.2558，相当于把中心值乘约 1.292。这个尾部适合保安全，但对当前
14B 两卡边界 case 太粗，产生 false reject。OOM guard 在该 case 上不是
主因。

## 4. 版本化显存锚点

### 4.1 锚点不是重训模型

锚点不会修改 physical-shares 系数，也不会把 167.35 GiB 从审计输出中
删除。它只在基础 P95 拒绝时，检查是否存在匹配且证据达标的历史锚点。

当前 14B 锚点至少要求：

- 2 次 runtime-complete、calibration-eligible 成功；
- 来自 2 个不同 job；
- 加上 legacy 佐证后至少 3 次成功；
- 完全相同配置下 0 次 OOM；
- 模型 config、模型 geometry 和 runtime mechanism 都有 SHA-256 绑定；
- GPU family、dtype、kernel、训练方式、卡数、ZeRO、GC、GBS 和 packing
  必须一致；
- 只允许把 cutoff 和 MBS 迁移到同等或更轻的范围；
- 基础 physical center 本身必须低于安全线；
- 不允许给 `unsupported` 域放行。

### 4.2 局部保护公式

当前锚点准入上界取历史保护值和模型中心保护值中的较大者：

```text
empirical_guard
  = maximum_observed_reserved * 1.02

model_center_guard
  = physical_center * 1.01

anchor_upper
  = max(empirical_guard, model_center_guard)
```

14B 两卡 case 的结果为：

```text
empirical_guard   = 129.94 GiB
model_center_guard = 130.87 GiB
anchor_upper       = 130.87 GiB
safe_limit         = 132.84 GiB
headroom           =   1.97 GiB
```

因此该候选从“基础 P95 拒绝”变为“版本化锚点准入”，随后进入两卡候选的
v4b 排序并排第 1。当前输出仍为 `shadow_only`，因为这批锚点证据不是
锚点冻结后新产生的独立验收数据。

### 4.3 为什么不用较轻数据集的均值直接覆盖

数据集平均 token 更短只能作为辅助信息，不能单独证明安全。激活峰值还会
受到长尾样本、动态 padding、MBS、GC、attention kernel 和 allocator 行为
影响。因此准入依据是“历史最大 reserved + 保护比例”和“物理中心 + 保护
比例”两者取大，而不是简单按平均长度缩放。

## 5. 历史实验锚点库的版本治理

### 5.1 新增锚点

新增证据时必须：

1. 生成新的候选配置文件和新的 registry 版本号；
2. 在 `previous_registry_sha256` 记录上一版本的完整 SHA-256；
3. 重新校验 canonical observation、hardware、模型配置、数据画像和
   runtime mechanism 的 SHA-256；
4. 重新计算证据数、OOM 数、历史峰值和保护上界；
5. 输出到新的版本化路径；程序拒绝用不同内容覆盖已有 registry；
6. 保留旧版本用于回放和回滚。

证据不足、出现完全匹配 OOM、来源文件漂移、运行机制变化或保护上界超过
安全线时，锚点必须保持 `rejected`，不能进入 Predictor。

### 5.2 锚点覆盖与模型覆盖是两件事

| 动作 | 作用范围 | 能否改变全局 physical-shares |
|---|---|---|
| 新增历史锚点 | 严格匹配的局部配置或同机制更轻形状 | 不能 |
| 发布新的显存模型版本 | 整个声明支持域 | 可以，但必须完成独立验收 |

禁止原地覆盖已有显存模型。候选模型必须先冻结，再使用未参与拟合、调参或
锚点构建的 holdout 做同集 before/after 回放。

### 5.3 允许发布新显存模型的最低条件

| 指标 | 最低要求 |
|---|---:|
| false-safe OOM | 0 |
| success P95 coverage | 至少 95% |
| safe success admission recall | 不低于当前 86.84% |
| reserved center mean APE | 不超过 6% |
| reserved center P90 APE | 不超过 12% |
| 目标边界 false reject | 必须减少 |
| 已支持分片的安全性 | 不允许退化 |

此外必须保存：

- 不可变候选模型；
- 预先声明的 calibration / holdout 切分；
- 同一冻结 holdout 上的 before / after 报告；
- 按模型规模、Full/LoRA、ZeRO、GC、MBS 和 cutoff 的分片指标；
- 审批记录、上一版本指针和 rollback 指针。

## 6. 仍需补的离线实验

### 6.1 Packing 的优先实验

第一优先级是 Qwen3-14B Full 的 `hold_off` case，因为它在静态侧显示明显
正收益。建议固定模型、数据、GBS、cutoff 和最终优化器配置，比较
`packing=false/true`，使用随机化 ABBA 顺序并至少 3 次重复。验收同时看：

- seconds per 1,000 logical samples；
- effective tokens/s 和 logical samples/s；
- peak reserved 与 OOM；
- 有效 GBS 误差；
- loss mask、跨样本 attention 和训练语义一致性。

随后补以下边界：

| 目的 | 建议覆盖 |
|---|---|
| 验证短序列负收益边界 | cutoff 512/2048，高 no-packing MBS |
| 验证正收益边界 | cutoff 4096/8192，MBS 1/2/4 |
| 验证训练方式 | 8B/14B 的 LoRA 与 Full |
| 验证数据分布 | 短文本、多轮、长尾、长上下文 |
| 验证模型迁移 | 至少一个未参与阈值校准的 dense Qwen 规模 |

这些实验必须在策略冻结后划出独立 holdout，不能继续用同一批点一边调阈值
一边报泛化准确率。

### 6.2 显存的优先实验

围绕 14B Full 两卡边界，离线补一个局部矩阵：

| 变量 | 建议值 |
|---|---|
| MBS | 1、2 |
| cutoff | 2048、4096、8192 |
| ZeRO | 2、3 |
| GC | 关、开 |
| 数据分布 | 短文本、多轮、长尾 |

不需要把所有笛卡尔积跑满。先选择物理中心位于安全线上下约 10 GiB 的
边界点，再补明显安全和明显 OOM 的控制点。每个关键边界至少重复 2 次，
并冻结 runtime mechanism。目标是区分：

1. 只有 Qwen3-14B Full 两卡这一小块需要锚点；
2. 还是当前 Full + ZeRO-3 + GC 的残差层级需要加入模型规模、MBS 或
   cutoff 特征重新分桶。

如果新增数据足够覆盖多个分片，再训练候选 physical-shares vNext；否则
继续使用窄锚点比修改全局尾部更安全。

### 6.3 严格验收顺序

```text
冻结 packing policy / memory candidate / anchor registry
  -> 锁定 calibration 与 unseen holdout
  -> 离线运行实验
  -> 生成 canonical observations
  -> 同集 before/after 回放
  -> 检查总体和分片门槛
  -> 人工审批
  -> 发布新版本或维持 shadow
```

推荐时不会把“证据不足”转换成临时 GPU 探针。结果只能是保守配置、
`hold_off`、`unsupported` 或显式拒绝。
