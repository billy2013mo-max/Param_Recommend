# RTX 4090 显存与吞吐模型泛化验证

日期：2026-07-29

## 1. 结论

4090 已经完成一套与 H800 同构、但参数单独拟合的模型：

- 显存：`physical-shares`，28 维中心模型 + 单侧 P95 安全头。
- 吞吐：`v4b`，70 维绝对吞吐头 + 独立 pairwise 排序头。
- 推理顺序：先用显存 P95 过滤，再在剩余候选集合上重新计算 v4b 排序。

本次验证得到的结论不是“4090 已完成严格泛化验收”，而是：

1. 在已经覆盖的 Qwen3 0.6B/1.7B/4B 文本 SFT 域内，显存中心估计和常规吞吐排序较好。
2. 显存模型没有把已观测 OOM 错放为安全配置，但 P95 头偏保守，会拒绝不少实际安全配置。
3. v4b 在 formal 长窗口同配置复测上稳定，但该结果不是跨配置泛化。
4. 留出整个模型量级以及 packing A/B 时，v4b 明显下降，严格泛化尚未通过。
5. 在 formal 回放中，端到端效果主要受显存模型保守拒绝限制，而不是受 v4b 排序限制。

因此，这套模型目前适合在已知域内做受控推荐和继续收集反馈，不适合宣称对任意模型量级、packing 或新模型家族都已经可靠。

## 2. 数据与无泄漏切分

4090 campaign 共收集 1136 次运行：

| 结果 | 数量 |
|---|---:|
| 成功 | 968 |
| OOM | 168 |
| 合计 | 1136 |

覆盖范围：

- 模型：Qwen3 0.6B、1.7B、4B
- 训练方式：Full、LoRA
- 数据分布：512、2048、4096、8192、16384、32768 六类长度分布
- 卡数：1、2、4 张 RTX 4090
- 变量：MBS、GBS、ZeRO、梯度重算、packing

严格切分如下：

| 模型 | 拟合数据 | 老实验验证 | 后来实验验证 |
|---|---|---|---|
| 显存 | 570 个原始 memory probe | 嵌套完整场景 5 折 CV | 241 个 screen、120 个 formal、46 个 packing=true |
| 吞吐 | 早期 throughput + screen，共 262 个成功候选 | 嵌套完整场景 5 折 CV、完整模型量级留出 | 120 个 formal、44 个 packing A/B |

formal 的 118 个成功配置都在 screen 中出现过。因此 formal 验证的是“短窗口到长窗口是否稳定”，不能解释为“未见配置泛化”。

训练吞吐模型时，模型输入中的 token 数、attention pair、FLOPs、HBM traffic 等全部由运行前静态数据 profile 重建；运行后的 token counter 只作为标签审计，不作为预测输入。

## 3. 显存模型

### 3.1 数学形式

中心预测：

```text
reserved_center
  = analytic_reference
    * exp(intercept + standardized_28_features @ beta)
```

其中 `analytic_reference` 由参数、梯度、优化器状态、activation、attention/logits workspace 和 ZeRO workspace 等物理分量相加得到。

安全预测：

```text
reserved_p95
  = reserved_center
    * exp(max(OOF_success_q95,
              exact_selector_OOM_guard,
              0))
```

推荐时只有满足以下条件的候选才会进入吞吐排序：

```text
reserved_p95 <= 0.95 * 4090_physical_memory
```

28 个名义特征全部在训练集中有变化，中心化矩阵秩为 25。

### 3.2 老实验结果

这里的老实验指标来自嵌套完整场景 CV：外层测试场景不会参与正则系数选择、中心拟合或 P95 尾部拟合。

| 指标 | 结果 |
|---|---:|
| 评估运行 | 570 |
| 成功 / OOM | 458 / 112 |
| 中心显存 MAPE | 11.11% |
| 场景等权 MAPE | 9.11% |
| 中心误差 P90 | 24.43% |
| 平均绝对误差 | 1.12 GiB |
| P95 覆盖率 | 95.41% |
| 错放 OOM | 0 / 112 |
| 安全成功配置放行率 | 84.98% |

这说明中心模型在老实验上具备可用精度，安全头实现了零错放 OOM，但代价是约 15% 的安全配置被拒绝。

### 3.3 后来实验回放

| 测试集 | 成功 / OOM | 中心 MAPE | 中心误差 P90 | P95 覆盖率 | 错放 OOM | 安全配置放行率 |
|---|---:|---:|---:|---:|---:|---:|
| screen 全部 | 215 / 26 | 6.39% | 13.78% | 100% | 0 / 26 | 66.25% |
| screen 未见场景 | 147 / 15 | 6.64% | 13.95% | 100% | 0 / 15 | 66.37% |
| formal 全部 | 118 / 2 | 5.82% | 11.62% | 100% | 0 / 2 | 78.82% |
| formal 未见场景 | 82 / 1 | 5.69% | 10.40% | 100% | 0 / 1 | 78.69% |
| packing=true | 44 / 2 | 6.48% | 15.74% | 100% | 0 / 2 | 77.27% |

显存中心预测的时间后移和未见场景表现较好，packing=true 也没有明显破坏中心精度。当前问题主要在安全头过于保守，而不是中心值不准。

## 4. 吞吐 v4b

### 4.1 数学形式

绝对头先给每个候选一个 log-throughput 估计：

```text
a_i = absolute_log_throughput(x_i)
```

排序头拟合同一用户场景内的吞吐差：

```text
r_i = pairwise_rank_score(x_i)
```

最终在同一候选集合内组合：

```text
prediction_i
  = mean(a)
    + lambda * (a_i - mean(a))
    + (1 - lambda) * (r_i - mean(r))
```

本次 4090 最终模型为：

- 绝对头：70 维 `full_factor`
- 绝对头目标：`direct_log_step`
- 绝对头 ridge alpha：0.01
- pairwise loss 权重：16
- 排序头：44 维 `compact_analytic`
- 排序头 ridge alpha：1
- `lambda`：0.75

70 个名义绝对头变量中有 56 个在 4090 训练数据内变化，中心化矩阵秩为 48。排序头 44 个变量中有 42 个变化，矩阵秩为 40。

### 4.2 指标说明

- Pairwise accuracy：同一场景任意两个候选，模型是否把更快的配置排在前面。
- Top-1 regret：模型选中的配置相比真实最优配置损失了多少吞吐；越低越好。
- 命中最优 90%：模型选中的配置是否至少达到真实最优吞吐的 90%。
- MAPE：预测绝对吞吐与实测吞吐的平均绝对百分比误差。
- P90 APE：90% 的候选绝对吞吐误差不超过该值。

### 4.3 验证结果

| 验证集 | 候选 / 可比较场景 | Pairwise accuracy | Top-1 regret | 命中最优 90% | 吞吐 MAPE | P90 APE |
|---|---:|---:|---:|---:|---:|---:|
| 老实验嵌套场景 CV | 262 / 79 | 95.78% | 0.74% | 97.47% | 13.55% | 27.93% |
| 留出完整模型量级 | 262 / 79 | 59.28% | 12.62% | 64.56% | 75.16% | 123.27% |
| formal 长窗口复测 | 118 / 36 | 96.30% | 0.28% | 97.22% | 13.29% | 26.35% |
| packing A/B | 40 / 18 | 38.89% | 25.64% | 38.89% | 45.08% | 87.31% |

完整模型量级留出的分项结果：

| 留出模型 | Pairwise accuracy | Top-1 regret | 命中最优 90% | 场景等权 MAPE |
|---|---:|---:|---:|---:|
| Qwen3 0.6B | 46.08% | 18.52% | 55.88% | 124.81% |
| Qwen3 1.7B | 79.89% | 6.63% | 79.31% | 35.00% |
| Qwen3 4B | 50.00% | 10.95% | 56.25% | 43.80% |

因此：

- v4b 在训练覆盖的模型量级和常规非 packing 配置上有效。
- formal 的好结果表明短窗口排序可以稳定迁移到长窗口。
- 但模型量级外推和 packing 因素泛化没有通过。
- 不能用 formal 的 96.3% 排序准确率替代完整模型留出的 59.3% 来宣称普适泛化。

## 5. physical-shares + v4b 端到端结果

端到端回放严格按照线上顺序：

1. physical-shares P95 过滤。
2. 在通过过滤的候选集合上重新计算 v4b。
3. 选择 v4b 排名第一的候选。

| 指标 | formal | packing A/B |
|---|---:|---:|
| OOM 候选错放 | 0 / 2 | 0 / 4 |
| 安全成功候选放行率 | 78.82% | 70.59% |
| 有真实安全候选的场景 | 66 | 22 |
| 没有任何候选被放行 | 14 | 5 |
| 选择到 OOM | 0 | 0 |
| 有返回结果时精确选中最优 | 94.23% | 52.94% |
| 全场景达到最优 90% | 74.24% | 40.91% |
| 有安全返回时平均 regret | 1.14% | 18.12% |

formal 中 v4b 单独可达到 97.22% 的最优 90% 命中率，但加入显存安全过滤后，端到端只剩 74.24%。原因是 14 个实际存在安全配置的场景被显存 P95 全部拒绝。

所以当前 4090 端到端主要矛盾是：

- 常规 formal：显存安全头过于保守。
- packing：显存保守拒绝和吞吐排序泛化同时存在问题。

## 6. 当前可用范围

可以受控使用：

- RTX 4090
- 当前 FA2 + Liger fused CE + fused AdamW runtime
- Qwen3 0.6B/1.7B/4B 文本 SFT
- Full/LoRA
- packing=false
- 训练数据覆盖的长度、卡数、ZeRO、MBS/GBS 邻域

尚不能宣称通过：

- 未见模型量级
- Qwen3.5
- VL 模型
- 大于 4B 的 4090 训练
- packing=true 的吞吐排序
- 其它 4090 主机、功耗/温度状态或运行时

## 8. 下一步

如果目标是让 4090 也达到“零 OOM，并且绝大多数场景能返回最优 90% 以内配置”，优先级应为：

1. 在不引入 false-safe OOM 的条件下，降低 P95 安全头的错误拒绝。
2. 新增至少一个未参与拟合的模型量级，做真正的前瞻模型留出。
3. 增加 packing A/B 候选密度，并把数据分布特征显式纳入 packing 吞吐校正。
4. 在冻结模型后再运行一批新实验，作为最终前瞻验收。
