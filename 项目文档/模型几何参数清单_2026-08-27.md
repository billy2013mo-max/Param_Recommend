## 1. 入库前必须知道的几个坑

| 现象 | 影响 | 涉及模型 |
|---|---|---|
| 新版 transformers 把 `torch_dtype` 改名为 `dtype` | 按「不存在就填 MISSING」的规则，`torchDtype` 只能填 MISSING，导致 20 个模型的 SQL 被注释掉。第 5 节附录 C 给了用 `dtype` 实测值填入的版本 | 全部 Qwen3-VL / Qwen3.5 / Qwen3.6 系列，以及 AutoGLM-Phone-9B、GUI-Owl-1.5-8B-Instruct、MAI-UI-8B、model |
| FP8 模型的 config 仍写 `bfloat16` | 按 config 建显存模型会**高估约 2 倍**；真实 dtype 只能从 safetensors 头部看出来（`F8_E4M3`） | Qwen3-14B-FP8、Qwen3.5-27B-FP8、Qwen3.6-27B-FP8 |
| MAI-UI-8B 的 config 写 `dtype=float32`，但磁盘权重全是 BF16 | config 与权重互相矛盾，应以磁盘为准 | MAI-UI-8B |
| nvfp4 打包权重的 tensor shape 不是真实参数量 | 头部求和得 19.8B，实际是 32B 模型，这个参数量不能入库 | blm_32b_nvfp4a4-gptq |
| Qwen3.6 的顶层 `model_type` 写的是 `qwen3_5`（不是 qwen3_6） | 按 model_type 分派会把它归到 Qwen3.5 | Qwen3.6-27B、Qwen3.6-27B-FP8、Qwen3.6-35B-A3B |
| OneReason-0.8B-pretrain-competition 的 `index.json` 里 `total_size` 是旧值 1871839232，实际文件只有 1602902800（差 14.4%） | 是 vocab 从 241920 缩到 176253 后 index 没更新。本文档报的是**实测文件字节**，不是 index 声明值 | OneReason-0.8B-pretrain-competition |
| Qwen3-Omni-30B-A3B-Instruct 的 `intermediate_size` 就是 768（= moe_intermediate_size） | 不是读错，config 里字面就是 768。这个模型没有 dense FFN 尺寸 | Qwen3-Omni-30B-A3B-Instruct |

## 6. 复现方式

扫描脚本：`/tmp/geom_scan.py`（只读，不 import torch）。核心是 safetensors 头部解析：

```python
with open(path, 'rb') as f:
    n = struct.unpack('<Q', f.read(8))[0]   # 前 8 字节小端 uint64 = 头部 JSON 长度
    hdr = json.loads(f.read(n).decode('utf-8'))
total = sum(prod(v['shape']) for k, v in hdr.items() if k != '__metadata__')
```
